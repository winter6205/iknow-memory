0. TL;DR：五个决策

D1 至 D5 五个核心决策
# 决策 一句话
D1 演进，不重构 gbrain 的混合检索栈与时间模型已领先多数参考实现；升级是“把图从检索辅助升为检索主结构”，不是推倒重来。
D2 Postgres 原生为主线，neo4j/AGE 为可选后端 neo4j 非必选（+1 JVM、Python 生态绑定、破全栈 Postgres 哲学）；主线用 entities/relations/aliases 三表 + tstzrange + PPR，AGE/neo4j 作生产可选。
D3 检索范式 = PPR 单步多跳 + 双层向量 + 社区摘要按需 借鉴 HippoRAG 2（PPR 取代迭代，便宜 10-30×）、LightRAG（双层 key-value，抛弃昂贵 Leiden）、DRIFT（全局问答按需触发，降 77% token）。
D4 抽取层 = LLM 三元组抽取 + canonical 实体合并 这是 BrainBench “+31 P@5” 的真正来源，也是 gbrain 当前最大缺口（links 全规则抽取、无实体合并）。GLiNER 前端 NER + LLM schema-guided 关系抽取 + 嵌入聚类消解。
D5 事实层 = 现有 bi-temporal 升级为 Graphiti 式 valid-window + 因果边 gbrain 的 facts 表已有 valid_from/valid_until/expired_at/superseded_by + halflife 衰减 + 4 档 temporal verdict。Graphiti 哲学已内置一半，补齐“不删除只失效 + 自动冲突失效 + 因果边”即可。
一句话愿景

把 gbrain 从“围着检索重排序打转的 SQL typed-edge 层”，升级为“以知识图谱为骨架、向量库为血肉、Postgres 为神经”的复合认知检索引擎，对应用户参考报告的 骨架 + 血肉 + 神经 三位一体。

1. 现状诊断：gbrain 向量记忆库到底有什么

1.1 读取侧：已经很重的混合栈（保留，不动主干）

hybridSearch（hybrid.ts:809）18 阶段主管线，四路召回 + 多级重排：

  • 四路召回：向量（pgvector HNSW cosine <=>）/ 关键词（tsvector BM25）/ 关系（typed-edge 图遍历）/ 源加权（SQL CASE）。
  • 融合：RRF 加权（RRF_K=60，hybrid.ts:47）→ cosine 重打分（0.7·normRRF + 0.3·cosine，hybrid.ts:1986）→ compiled_truth ×2.0（hybrid.ts:48）。
  • post-fusion 5 级：backlink（0.05·log）/ salience / recency 半衰期 / title-phrase / graph-signals（邻接×1.05、跨源×1.10、会话×0.95）/ alias_resolved×1.05。
  • 精排：cross-encoder rerank（zerank-2，官方 reshuffle 60% top-1）→ alias hop×1.10 → autocut 断崖 → token-budget。
  • 三档 mode bundle：conservative / balanced / tokenmax，knobs_hash v=11 防缓存污染。
判断

这套读取侧是 gbrain 的护城河，升级只加旁路（PPR 臂、图遍历臂增强），不重写主干。

关键发现

gbrain 的时间模型已相当扎实（append-only + soft-supersede + halflife + 4 档 temporal verdict）。Graphiti 的 bi-temporal 哲学 gbrain 已内置一半。这意味着 D5 是“补齐”而非“新建”。

1.3 图子系统：SQL typed-edge，不是真图（主战场）

  • 节点 = pages 行（单一 type 字段），无 property graph、无 node-level embedding（embedding 只在 chunk 级）。
  • 边 = links 行（link_type 单值，13 个封闭词汇：founded/invested_in/works_at/mentions…），无 weight/confidence/可变时间戳。
  • 遍历 = 纯 SQL 递归 CTE（relationalFanout，深度默认 2 硬顶 3，postgres-engine.ts:3039），within-source（跨源禁用，安全审计特性）。
  • 实体消解 = 4 步 slug 字符串解析 + alias 双表（slug_aliases/page_aliases），无 canonical_entity_id 合并模型，“张总↔张三”做不到真正合并。
  • 社区/全局 = 完全没有 Leiden/分层摘要/map-reduce；synthesize_concepts 只是 flat tag-bucket + LLM narrative。
  • code 子图（code_edges_chunk/symbol）独立于 links，检索管线不消费。

3. 核心决策详解

D1演进，不重构

依据：gbrain 读取侧混合栈 + 分层时间模型已领先多数 RAG 参考实现（治理、真向量臂、RRF、bi-temporal facts、4 档 temporal verdict 都已内建）。BrainBench +31 P@5 证明现有“图 + 抽取质量”方向正确，只是图还停留在 SQL typed-edge。

动作：所有升级以“加旁路 / 加列 / 加表 / 加 cycle phase”形式接入现有 seam（见 §6），不动 hybridSearch 主干、不动双引擎 lockstep 契约。

D2存储选型：Postgres 原生主线

依据（2026 选型调研）：

  • neo4j 非必选：引入 = +1 JVM 进程 + Bolt 协议 + 跨库双写，且 neo4j-graphrag 高级包是 Python 生态（gbrain 是 TS/Bun），打破“全栈 Postgres”哲学。杀手锏（GDS 图算法）在 gbrain 当前规模（百万 chunk 级以下）overkill。
  • Kuzu 已死（Apple 2025-10 收购并 archive），排除。
  • FalkorDB 快（比 neo4j ~9×）但需独立 Redis 进程，破哲学，排除主线。
  • Postgres 原生只有两候选：Apache AGE（openCypher，但 PGLite 兼容性是生死未知数，无成功案例）vs pgvector+递归 CTE（兼容完美、表达力弱）。

动作：

  • 主线：entities(id, source_id, name, type, summary, embedding) + triples(subject_id, relation, object_id, evidence_chunk_id, confidence, valid_window tstzrange, superseded_by) + entity_aliases(entity_id, alias_norm) 三表，纯 Postgres，pglite/postgres 双引擎同形 DDL。
  • 多跳：应用层 PPR（SQL 递归 CTE 实现，或 graphology 内存图），不依赖 DB 图算法。
  • 可选后端：graph-backend/ 适配器层，生产 PG 自托管可切 Apache AGE（openCypher），未来真需要 GDS 再评估 neo4j。prototype 阶段硬验证 PGLite 能否加载 AGE，不能则主线不变。

D3检索范式：PPR + 双层向量 + 社区按需

依据（2026 算法前沿）：

  • HippoRAG 2（ICML 2025）：PPR 单步多跳比迭代检索便宜 10-30×、快 6-13×，不牺牲事实问答；其 error analysis 明确“抽取质量决定上限”，与 gbrain BrainBench 互证。
  • LightRAG（EMNLP 2025）：双层 key-value（low-level 匹配实体 / high-level 匹配关系主题）+ 增量更新，抛弃昂贵 Leiden 社区摘要。
  • DRIFT（GraphRAG 0.4）：全局问答按需触发，token 降 77%。

动作：

  • 新增 PPR 检索臂：向量召回 chunk → 锚到实体节点（node-level embedding）→ 在 triples 图上跑 Personalized PageRank → 重排注入 RRF。作为 hybridSearch 第五臂（与 relational 臂并存，mode bundle 控制开关）。
  • 双层关键词：现有 tsvector 臂扩展为 low-level（实体名）+ high-level（关系/主题）双查询。
  • 社区摘要：新增 cycle phase synthesize_communities，离线批处理、按需触发（仅全局/主题问题走），不进常规检索热路径。

D4抽取层：LLM 三元组 + canonical 实体合并（+31 的来源）

依据：gbrain links 全规则抽取、无实体合并，这是距 GraphRAG 最大缺口，也是 BrainBench “抽取质量 +31” 的真正含义（现状靠 compiled_truth 人工精华 + alias 折叠近似，非自动抽取）。2026 最佳实践：GLiNER 前端 NER + LLM schema-guided 关系抽取 + 嵌入聚类消解。

动作：

  • 新增 cycle phase extract_triples：复用现有 LLM-as-extractor 管线（已有 injection sanitize / dream_generated 反自食 gate / parse barrier / 4-strategy JSON fallback），prompt 拓为 5W1H + 关系补全的统一三元组抽取，输出 (subject, relation, object, evidence_span, confidence) 写 triples 表。
  • canonical 实体合并：新增 entities 表 + entity_aliases，LLM 按 type 聚类（用抽取阶段的 one-line description 作消歧上下文，抓“Edwin Aldrin↔Buzz Aldrin”零字符重叠合并）；规模化先按嵌入相似度/同姓氏 blocking 切 50-100 小批。
  • 增量：新文档只抽取 → 只与已有 canonical 集合消解 → 追加边（不全量重建），复用现有 watermark/idempotency 机制。
  • 现有 links 表保留（规则边作为高置信先验），与 triples（LLM 边）并存，检索侧加权融合。

D5事实层：bi-temporal 升级 + 因果边

依据：gbrain facts 已有 valid_from/valid_until/expired_at/superseded_by + halflife + 4 档 temporal verdict。Graphiti 哲学已内置一半。缺“不删除只失效的显式语义 + 自动冲突失效 + 因果边 + 字段级版本”。

动作：

  • facts/triples 的时间列统一升级为 tstzrange valid_window + GiST 索引，检索按 valid_window @> $time 切片（可查“曾经是/现在是/T 时刻是”）。
  • 自动冲突失效：extract_triples/extract_facts 写入时跑 contradiction check（复用 eval_contradictions_cache 的 4 档 verdict），冲突时旧事实写 invalid_at（不删除），新事实 supersede，对齐 Graphiti 的 ADD/SUPERSEDE/NOOP 算子。
  • 因果边：triples.relation 词汇表加 caused/enabled/prevented，抽取时识别；为未来因果推理/反事实留接口（P2，不阻塞）。

5. 数据模型演进

5.1 新增表（pglite/postgres 双引擎同形）

-- canonical 实体（骨架节点）
CREATE TABLE entities (
  id          BIGSERIAL PRIMARY KEY,
  source_id   TEXT NOT NULL DEFAULT 'default',
  name        TEXT NOT NULL,              -- canonical 名
  type        TEXT NOT NULL,              -- person/org/product/concept/event/location
  summary     TEXT NOT NULL DEFAULT '',   -- 跨文档合成的 profile（hub 节点）
  embedding   VECTOR(1536),               -- node-level 向量（D3 锚点）
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (source_id, name, type)
);

-- 实体别名（消解入口）
CREATE TABLE entity_aliases (
  id          BIGSERIAL PRIMARY KEY,
  entity_id   BIGINT NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
  alias_norm  TEXT NOT NULL,              -- 复用 normalizeAlias()
  UNIQUE (entity_id, alias_norm)
);

-- 三元组（骨架边 + 事实）
CREATE TABLE triples (
  id                BIGSERIAL PRIMARY KEY,
  source_id         TEXT NOT NULL DEFAULT 'default',
  subject_id        BIGINT NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
  relation          TEXT NOT NULL,        -- 含因果词汇 caused/enabled/prevented
  object_id         BIGINT REFERENCES entities(id) ON DELETE CASCADE,
  object_literal    TEXT,                 -- 宾语为字面值时（如 "20%"）
  evidence_chunk_id INTEGER REFERENCES content_chunks(id) ON DELETE SET NULL,
  confidence        REAL NOT NULL DEFAULT 1.0,
  extractor         TEXT NOT NULL DEFAULT 'llm',  -- 'llm'|'rule'|'manual'
  valid_window      TSTZRANGE,            -- bi-temporal（D5），GiST 索引
  superseded_by     BIGINT REFERENCES triples(id),
  created_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_triples_subject ON triples(subject_id);
CREATE INDEX idx_triples_object ON triples(object_id);
CREATE INDEX idx_triples_valid ON triples USING GIST (valid_window);

5.2 现有表演进（加列，不破坏）

  • links：加 weight REAL DEFAULT 1.0、confidence REAL DEFAULT 1.0（规则边置信度），保留全部现有列与约束。
  • facts：valid_from/valid_until 迁移为 valid_window TSTZRANGE（双写过渡），保留 expired_at/superseded_by。
  • pages：加 entity_id BIGINT REFERENCES entities(id)（page↔entity 关联，可选）。

PGLite WASM 能否加载 Apache AGE。不能，则主线（SQL 三表 + 应用层 PPR）不变，AGE 仅作生产自托管可选。

8. 评估与验证

  • 检索端：现有 BrainBench（P@5/R@5，search/eval.ts，默认 k=5）+ longmemeval + replay × 3 modes，paired bootstrap + Bonferroni。升级后对比 baseline，P0 目标：P@5 从 49.1 进一步提升。
  • 抽取端（新增）：eval extract-triples 子命令，gold set + P/R/F1（entity resolution + triple correctness），对齐 Anthropic Cookbook 的 F1 闭环（改 prompt → 重跑 → 看 F1 漂移）。
  • 质量端：takes-quality 5 维 rubric 保留；新增 RAGAS 四维（faithfulness/context recall 重点）。
  • 双引擎：test/e2e/engine-parity.test.ts pin 所有新表 DDL。

9. 风险与陷阱（二次开发必读）

双引擎 lockstep任何新表/新列必须 pglite + postgres 同形 DDL，parity 测试 pin（gbrain 铁律）。
缓存污染改任一检索 knob 需同步 KNOBS_HASH_VERSION（现 v=11）；PPR 臂进 mode bundle 要折进 knobs_hash。
PGLite × AGE 未知无成功案例，prototype 硬验证，不做假设。
跨源遍历是安全审计特性relationalFanout within-source 限制不可绕过；PPR 臂默认同样 within-source，跨源需独立 security review。
mentions 密度炸弹规则 mentions 边默认排除在遍历外（link_source IS DISTINCT FROM 'mentions'）；LLM triples 需设 confidence 下限防噪。
LLM 抽取成本/一致性复用现有 gate（sanitize/反自食/parse barrier）；prompt caching + Message Batches API 压成本；抽取质量是上限（HippoRAG error analysis 互证）。
compiled_truth 是人工精华×2.0 boost 不可动，它是现状 P@5 的承重墙；三元组抽取是“自动化补强”，不替代人工 compiled_truth。
官方 RETRIEVAL.md 流程图过时真实顺序以 hybrid.ts 为准（dedup → rerank → autocut → slice → budget）。
