02向量臂：余弦相似度搜 chunks

向量臂是原有路径。query 被嵌入成向量，然后在 chunks 里按余弦相似度排序，返回 top-K。

它解决什么单跳事实查询——答案落在某一段文本里，且该段在嵌入空间靠近 query。这是纯向量检索最擅长的场景。
它的局限如果答案需要"跨片段求交"（如"研究阿尔茨海默的斯坦福教授"），向量臂可能漏——因为每段是孤立编码的，chunk#1 提了阿尔茨海默、chunk#5 提了斯坦福，但没有任何 chunk 同时提到两者。这就是图臂要补的。

03图臂：实体链接 → one-hop → chunks

图臂走三步：找种子实体 → 沿三元组走一跳 → 回到原文 chunks。下面这张图是核心，点击节点看详情。

实体 (entities) 三元组 (triples) 原文 chunk 图臂路径
src/core/retrieval/query-builder.ts · buildSeedEntitiesSql
SELECT id, canonical_name FROM entities WHERE embedding IS NOT NULL AND merged_into IS NULL AND retired = false -- 只留"存活"实体 ORDER BY embedding <=> $1::vector -- 余弦距离升序 LIMIT $2 -- top-K
src/core/retrieval/query-builder.ts · buildOneHopChunksSql
SELECT c.id, c.content, c.source_ref, c.valid_from, c.valid_until FROM triples t JOIN chunks c ON t.source_chunk_id = c.id -- ← 这一行就是"一跳" WHERE (t.head_id = ANY($1::uuid[]) OR t.tail_id = ANY($1::uuid[])) AND t.valid_window @> $2::timestamptz -- 三元组在查询时刻有效 AND c.valid_window @> $2::timestamptz -- chunk 也在查询时刻有效 ORDER BY t.confidence DESC -- 高置信优先 LIMIT $3
为什么只能"一跳"？query-builder.ts 里有个 assertSingleHop 守卫，写死三条规则：JOIN chunks 恰好出现 1 次、禁止 WITH RECURSIVE（递归 CTE）、禁止 UNION（第二跳）。这是刻意的——P0 只做一跳（实体回证据），多跳是 P1 PPR 的正规课题。
valid_window 双侧过滤既要求三元组在查询时刻成立，也要求原文 chunk在查询时刻有效。这就是"可时间切片"在检索层的体现——旧的事实不会被当作当前事实返回。

04RRF 融合：两臂结果怎么合并

两臂各返回一批带排名的结果。RRF（Reciprocal Rank Fusion）把它们合并成一个排序列表——核心公式：

score = w / (k + rank)　·　k = 60　·　wvec = 1, wgraph = 1
同一 chunk 在两臂都出现 → 分数相加（双命中叠加）

chunk 合计 命中的臂
#42 0.0328 向量 + 图

#07 0.0159 向量
关键洞察chunk#42 在两臂都命中（向量语义 + 实体关系两个独立信号），RRF 分数叠加 → 排到最前。这就是"双信号比单信号可信"的体现。

05降级契约：图臂挂了也不影响检索

这是 SPEC 3 最值得记住的设计。检索永远不因图臂失败而失败。图臂遇到任何异常，都降级成"图臂无效"，返回纯向量结果，并标记 degraded: true。

0 个种子实体

命中数 < floor

Q1图臂的"一跳"指的是什么？
SPEC 3 图臂从实体出发，经过三元组回到 chunks。这个"一跳"具体是什么？
A从实体沿三元组走到另一个实体（实体→实体）
B从种子实体出发，沿三元组的 source_chunk_id 一次 JOIN 回到原文 chunks
C在整个知识图谱上做多次跳跃遍历（多跳）
Q2RRF 双命中为什么更靠前？
chunk#42 在向量臂排第 2、在图臂排第 5。RRF 融合后它的分数是：
A只取较高的那个：1/(60+2) ≈ 0.0161
B两个相加：1/(60+2) + 1/(60+5) ≈ 0.0315
C取平均：(1/(60+2) + 1/(60+5)) / 2 ≈ 0.0157
Q3图臂的 fail-open 降级
图臂执行时 Postgres 挂了。retrieve 工具会怎样？
A整个 retrieve 调用抛错，host 收到异常
B返回纯向量结果，并标记 degraded: true
C返回空结果 { chunks: [] }，假装没事
Q4valid_window 双侧过滤
用户 3 月说"在北京"，8 月说"搬到上海"。查询时刻 valid_at = 2026-07 时，图臂会返回哪个三元组？
A(用户, 位于, 北京)——因为 7 月时上海那条还没生效
B(用户, 位于, 上海)——因为是更新的
C两条都返回，让 LLM 自己判断
