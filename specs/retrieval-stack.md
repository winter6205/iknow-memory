> **Status:** draft（假设清单 R1–R4 已定稿，取值已写回 §B1；本节不再有待确认项）。

> **Predecessors:** `specs/p0-schema.md`、`specs/p0-extraction.md`、`specs/p0-integration.md`、`specs/p0-wiring-closure.md`、`specs/bm25-retrieve.md`、`specs/neo4j-graph-arm.md`、`specs/retrieve-graph-priority.md`、`specs/retrieve-p5.md`、`specs/p0-eval.md`、`specs/retrieve-rerank-llm.md`、`specs/retrieve-graph-quality.md`、`specs/retrieve-community.md`；ADR-0001、ADR-0002。
> **Assumption gate:** 已关闭 —— R1–R4 已定稿，取值写回 §B1（该表各项均为定稿契约，不再是建议值）。

## Objective

把定档 B 的检索栈落成可判定的契约，并给这条栈配一套**能出数字**、且能与 fin 侧报告**合并成一份结论**的评测与并发验证。

做什么：

1. **落地定档 B** — 图为主路径（Neo4j 多跳），向量与关键词在两处被调用，Elasticsearch 作为精度层承担中文分词、Okapi BM25、短语查询、字段加权；向量索引在既有 Postgres 向量扩展上原地建成；权威源与派生索引分离，派生索引可从权威源重灌。
2. **承接"不二次切分"** — 切分的唯一权威是 fin；本仓库对推送内容不做任何二次切分，按原样存储与召回。
3. **检索能力默认启用所有功能** — 不做成可选开关矩阵让运营方逐个打开；默认配置下能力全部开启，偏差可被自检命中。
4. **消灭静默失败** — 凭证缺失、地址缺失、调用失败、后台路径失败都不许静默；降级信号的形态、置位规则与消费规则由「跨仓对齐基线」统一定义。
5. **评测体系** — 注入真实数据、覆盖多种文件格式与多种查询类型、规模有下限、支持逐个开关做消融实验、输出相对基线的**百分比数字**。
6. **并发测试** — 给出目标并发数与判定阈值，作为可重复执行的入口，而不是一次性人工压测。

谁用：MCP 调用方（host，生产形态下即 fin）；跑入库/抽取/投影/评测/压测入口的运营方；按本契约实现的人。

成功长什么样：默认配置下这条栈的每一项能力都在场；任何一项能力被关掉，评测报告能说出「P@5 相对基线变化了百分之几」；并发入口能在固定并发下跑完并给出错误率与 p95/p99 数字；权威源与派生索引的关系可验证——派生索引删掉重建，数据不丢、检索质量不回归；没有任何一条失败路径是静默的。

## 检索架构（已定稿，本 spec 只做契约化，不重新讨论）

```text
【找实体】向量检索 + Elasticsearch → 定位实体 → 种子
        ↓
【主检索】Neo4j 从种子出发多跳（PPR）→ 真正的信息
        ↓
   图上没找到实体？
        ↓
【回退】向量检索 + Elasticsearch → 直接检索文本
```

三条要点，本契约的每一条检索相关标准都以此为准：

1. **向量只有一个能力**，不是「找种子的向量」和「回退的向量」两种角色。同一个 **vector search** 在两个环节被调用。
2. **图是主路径**。真正的信息检索发生在 **Neo4j graph arm** 上（种子 → **PPR** → 经 `source_chunk_id` 映射回 **chunk**）。
3. **Elasticsearch 是精度层**，在「找实体」与「回退」两处都在场，作用是把结果收紧。向量与关键词是**互补搭档**，不是二选一，不做主备切换。加它就是为了精度。

与既有 CONTEXT.md 的对应关系（原文引用，不重新定义）：

- 「找实体」+「回退」两处的关键词臂 = **BM25**（Okapi BM25 词法排序）。
- 「主检索」= **Neo4j graph arm** / **PPR**；两臂合流后的 Host 顺序 = **hybrid retrieval**（graph-priority：图命中领先，空则 **RRF fusion (k=60)** 的向量+关键词列表，图命中不足 `limit` 时由该列表补位）。本 spec 与 **hybrid retrieval** 的 graph-priority 语义**一致**并显式保留，不是改判。
- 后处理 = **rerank**（默认开启，见改判 C-3）、**neighbor evidence**、**community**（topic retrieve）。
- 时间过滤沿用 **valid_window** / **valid_at**（`valid_window @> valid_at`，左闭右开）。
- 权威与派生：沿用 ADR-0001 与 CONTEXT.md 的 flagged ambiguity「Postgres authoritative, Neo4j read-only projection」。本 spec 把「派生、可重建」这一条从图投影**扩展**到检索索引（向量索引与词法索引都是派生物，可从权威源重灌）——这是一个新增决策，见改判 C-7 与待写入清单。

### B1 统一数字口径

| 项 | 统一值 | 判定 |
| --- | --- | --- |
| 并发 L1（检索 / 读取路径，不含 LLM） | 并发 16、持续 120 秒、读写比 9:1、总请求数 ≥ 1200 | 错误数 = 0；5xx < 1%；p50 / p95 / p99 全部落盘 |
| 并发 L2（完整 run，含 LLM） | 并发 8、持续 120 秒 | 错误数 = 0；p50 < 60 s、p95 ≤ 120 s |
| 并发幂等场景（全写） | 并发 16、持续 120 秒 | 错误数 = 0；压测前后块总数增量 = 0 |
| 延迟阈值 | p95 ≤ 800 ms、p99 ≤ 2000 ms（预热请求不计入） | 仅作用于并发 L1；L2 用其自身的 p50 / p95 判据 |
| 数据集规模 | 源文档 ≥ 140 篇（≥ 7 种格式 × 每格式 ≥ 20 篇）、切分后块 ≥ 20000 且 ≤ 120000、查询 ≥ 100 | 全部为真实样本；合成样本与无来源样本不计入计数 |
| 查询分档 | CI 契约集 40 题（脚本化、无 LLM 判定）；全量集 ≥ 100 题，四类各 ≥ 10% | CI 集每次提交跑；全量集每周一次 |
| 语料来源与许可 | 分三级，见本节末 | 缺来源或标记为合成的样本不计入计数 |
| 指标集 | P@5、R@5、Recall@20、nDCG@10、MRR、引用门通过率（由 fin 侧产出）、图臂命中率、错误率、延迟 p50 / p95 / p99 | 每个配置全部输出，缺任一项该配置即不通过；引用门通过率由 fin 侧在同一份运行结果上产出，两侧报告合并后指标集完整 |
| 消融矩阵 | 10 个配置 = 全开 1 + 逐项关闭 8 + 全关 1；消融跑 20–40 题的脚本化子集；每配置重复 ≥ 3 次，落原始值与中位数 | 可独立开关的能力项恰为 8 个（见 B4） |
| 幂等基准 | 同一批次连续推送 3 次：块总数增量 = 0，块标识集合不变 | 失败推送具名返回，不计入幂等断言 |
| 评测资源预算 | 消融 30 次合计约 3–8 小时，夜间窗口串行；全量 100 题每周一次、约 1–2 小时；两个并发场景合计 ≤ 30 分钟（含预热） | 压测机与服务分离；语料全本地 |

**语料来源三级（定稿）**

- **一级 · 可引用**：冻结的 10-Q PDF（上游版本已固定）与 EDGAR 官方主 iXBRL HTML。此级产出 locator 与引用证据。
- **二级 · 仅供结构化查数**：XBRL instance XML 与公开数据接口的 XBRL JSON（限流 10 req/s）。供事实表，不产出引用证据。
- **三级 · 派生**：由一级真实内容经确定性导出器生成的 md / docx / xlsx / pptx。内容全部来自真实语料；导出器固定模板与字节序以保证可复现；清单须标 `origin=derived` 与 `derived_from_sha256`；引用身份仍回指原生文档，不新增第二套 locator 契约。
- **禁止**：以数据接口的渲染片段充当 filing 身份；无来源或合成样本计入计数；并发压测访问外部数据源；未达既定门槛即引入额外压力包。
- **许可纪律**：每个引入上游数据的改动都固定上游版本并复核许可与归属。

> 上表各项均为**定稿契约**，不再是建议值。

### B2 部分失败语义（统一）

1. **一臂成功即放行**：一次检索中至少一个臂成功返回（命中或空结果皆可），响应放行。**仅当存在失败或无法尝试的臂时**（无法尝试指按 B3 规则 1 因凭证或地址缺失而未启动）才在信封上置**降级标记**并逐项列出原因；全部臂均成功（无论命中与否）**不**置标记——与 B3 规则 3 及 B2 第 5 条第二类一致。
2. **全部失败即具名失败**：所有臂都失败时返回具名失败（typed error），不返回空结果冒充"命中为空"，也不返回未标记的部分结果。
3. **向量臂失败且主路径无命中**视为全部失败——此时回退能力已失，不构成"一臂成功"。
4. 放行后的降级结果**可用但必须可见**：调用方按 B3 消费，不得因为降级而放宽引用门或静默重试。

5. **无效输入与合法空结果必须区分**（两侧统一，不得混同）：
   - **无效输入**——调用方传入的非法入参（空查询、空内容、空批次等）：返回具名失败（typed error），**不**返回空结果冒充"命中为空"，且**不**按 B3 置 `degraded`（入参非法不是能力失败；误置位即判定失败）。
   - **合法空结果**——入参有效、能力已尝试但未找到任何命中：返回成功响应与空结果列表，不抛异常，且按 B3 规则 3 **不**置 `degraded`。
   - 任一侧把无效输入当作合法空结果处理，或把合法空结果当作失败，均为**契约违反**。

### B3 降级信号：形态与消费

- **形态**：每次检索响应在既有信封上带一个可选字段 `degraded`（布尔）与 `degraded_reasons`（有限枚举列表，每项指明是哪一个能力项、属于"未尝试"还是"尝试失败"）。`degraded` 缺省即未降级。**字段名逐字为 `degraded` 与 `degraded_reasons`，两侧不得另立名称、另作翻译或改用等价表述。**
- **置位规则**（唯一权威定义）：
  1. 默认启用的能力因凭证或地址缺失而**无法尝试** → 置位；
  2. 已尝试的能力调用失败 → 置位；
  3. 能力已尝试但未找到任何命中 → **不**置位；
  4. 调用方显式关闭的能力 → **不**置位。
- **禁止的静默形态**：不得用确定性伪向量、空结果、静默跳过、无标记的顺序回退代替降级信号。任何失败路径必须留下可断言的痕迹——信封标记、具名错误码、可列举的失败记录，三者必居其一。
- **消费规则**：调用方必须读取该标记；为真时不得把该次结果当作完整结果使用，须按 B2 处置、向用户侧暴露可见信号、记录原因。**把降级当空结果处理或忽略该标记，是契约违反。**

### B4 跨仓契约字段

| 契约项 | 定义（两仓共用，不得各写一套） |
| --- | --- |
| 不二次切分 | 解析与切分的唯一权威是 fin，fin 推送的文本即最终文本。检索服务对推送内容不做任何形式的二次切分、截断、重组或归一化改写，按原样存储与召回；召回返回的块文本与推送文本逐字节相同。 |
| `source_ref` 拼写与粒度 | 拼写逐字为 `source_ref`；内容 = fin **locator** `{document_id, version, unit}` 的稳定序列化；粒度为**冻结单元级**（同一冻结单元的所有块共享同一个 `source_ref`）。`source_ref` 不是块身份。 |
| 幂等键 | =（`source_ref`，内容标识）二元组；内容标识 =（块文本 + 归一化规则版本 + 解析规则版本 + 参数表版本）的确定性哈希。同一幂等键重复推送不产生第二份写入，返回同一批块标识。 |
| 内容失效触发条件 | fin 的冻结单元文本发生变更（同一 `{document_id, unit}` 产生新 `version`，或解析规则版本 / 参数表版本变更导致块文本变化）时，fin 必须对该冻结单元的旧块发起失效。 |
| 内容失效语义 | 检索服务的失效动作 = 关闭时间有效区间，使该内容不再被任何查询时刻命中；不物理删除；失效幂等、可重复执行，并留下可查询的失效记录。 |
| 消融的 8 个能力项 | 键名逐字固定，两侧不得另立名称或改用等价表述：`vector`、`keyword_bm25`、`cjk_segmentation`、`phrase`、`field_boost`、`graph_ppr`、`rrf`、`rerank`。中文对照：向量检索、关键词检索（Okapi BM25）、中文分词、短语查询、字段加权、图多跳检索（主路径）、RRF 融合、重排。检索服务侧须公布上述键名枚举；fin 侧的静态检查以该枚举为准，枚举变更须两侧同步。 |
| 后台路径失败契约 | 异步入库 / 抽取 / 投影等后台路径的失败必须落成可列举、可重放的具名失败记录；重试是幂等的；不静默丢弃。 |

| 降级标记（`degraded`） | 见 B3。检索服务侧既有词条 **degraded=true** 的置位规则以 B3 为准（B3 是其改判后的唯一权威定义）。 |
| 幂等键 | 见 B4。 |
| 内容失效 | 见 B4。 |
| 消融 | 逐个关闭单个能力项、与全开 / 全关基线对照，同时给出百分比与绝对值差异的评测方法。 |

### B6 本章的验收

两份 spec 的本章正文（自 `## 跨仓对齐基线` 标题行之后起，到下一个 `## ` 标题行之前止，去掉首尾空行）**逐字节相同**：取两侧该段正文分别计算 sha256，两值相等则通过，不等则失败。两侧文件路径由执行方在运行时给出，不写死在本 spec 内。

## 必须补齐的能力（对侧已建票，本 spec 落实）

| # | 现状缺口 | 本 spec 的落实 |
| --- | --- | --- |

## Boundaries

- **Does:**
  1. 定档 B 落地：Elasticsearch 承担中文分词 / Okapi BM25（k1、b 可调）/ 短语查询 / 字段加权；向量索引在既有 Postgres 向量扩展上原地建成并降维；图（Neo4j PPR）作为主检索路径默认启用。
  2. 权威源与派生索引分离：提供从权威源重灌派生索引的入口，并证明「删索引 → 重建 → 数据不丢、质量不回归」。
  3. **不二次切分**：推送文本即最终文本，按原样存储与召回（§B4）。
  4. 检索能力默认启用所有功能：默认配置下能力开关矩阵全开，并配备启动自检/静态检查命中关闭项。

  6. 消灭静默失败：凭证 / 地址缺失、调用失败、重排失败、精度层失败、建索引失败、后台路径失败——每一条都留下可断言的痕迹（§B2、§B3）。

## Success Criteria

每条二元，映射到一条命令或一个可测量检查。外部依赖（Elasticsearch / Neo4j / 真实 Postgres）在**配置层面未提供**时按项目惯例 **loud skip**（不静默通过）；**已配置但在调用期失败**时按 §B2 / §B3 置 `degraded` 为 true 并在 `degraded_reasons` 中具名，不静默。数字一律取「跨仓对齐基线」，本 spec 正文不再另设一套。字段名逐字见 §B3。

### A. 检索栈定档 B

1. **中文分词生效**：向一个已入库的中文 **chunk** 发起查询，该查询与目标文本**语义不相近**、但共享中文词元；检索结果 top-5 含该 chunk，同一 fixture 在关闭中文分词的配置下 top-5 不含该 chunk。同时对一段连续中文文本断言词法侧分析接口返回的词元数 ≥ 2（返回 1 即失败）。
    - **「语义不相近」的度量（本条唯一判据，三条断言全过才算"不相近"）**：
      - **M1 相对判据（主判据）**：fixture 提供**锚定样本对清单**（条数 ≥ 3；每条含：查询句、目标 chunk 文本、一条与目标 chunk 语义相近的对照句）。对每条锚定对，向量由本次评测运行所用的同一嵌入模型产出，断言 `余弦相似度(查询句, 目标 chunk) < 余弦相似度(对照句, 目标 chunk)`。清单条数 < 3 即本条失败（不接受空清单蒙混）。
      - **M2 绝对兜底**：`余弦相似度(查询句, 目标 chunk) ≤ 0.5`。
      - **M3 共享中文词元**：查询句与目标 chunk 文本经词法侧分析接口产出的词元集合交集 ≥ 1（否则"共享中文词元"不成立，本条失败）。
    - 命令：`npm run eval:stack -- --config zh-segment-off`。
2. **向量索引**：Postgres 侧 chunk 向量的索引存在（索引 introspection 命中 1 条），一次向量检索的执行计划中 chunks 表的访问方式不是顺序扫描（EXPLAIN 断言）；**索引维度上限 = 2000**（既有 Postgres 向量扩展的索引维度上限），该上限从配置读取并断言 > 0 且为有限值（为 0 / 缺失 / 占位值即失败），且被实际用于维度越界判定；配置中的向量维度 ≤ 该上限，越界时进程启动以非 0 退出并给出 typed error；构造「索引无法建立」的条件时进程以非 0 退出并给出非空错误信息（退出码 = 0 即失败）。四条全过才算通过。上限随扩展版本变化时在配置中声明，spec 只约束"非 0 且参与判定"。
3. **Okapi BM25 可调**：k1 / b 经配置改变后，同一查询在同一语料上的排序发生变化（top-5 id 序列不同，即"可调且生效"）；默认配置下 k1 与 b 均从配置读取，且为 > 0 的有限值（未取到值 / 为 0 / 非有限值即失败）；k1 / b 取非法值（≤ 0、非数值、非有限值）→ typed error。**默认值不进本 spec**，由实现者在配置默认值中给出（§实现者余地）。
4. **短语查询参与排序**：精确串命中的 chunk 排在仅单词元命中的 chunk 之前（top-5 内相对次序断言）。
5. **字段加权生效**：改变字段权重后，同一查询的 top-5 id 序列发生变化；权重为 0 的字段不贡献命中。
6. **权威源可重灌**：删除派生索引后执行重灌入口，落库的 chunk 行数与重灌前相等（差 = 0）。
7. **重灌不回归**：重灌后同一评测集快照的 run-level P@5 ≥ 重灌前 P@5 − 0.02，且没有任何查询从「有命中」变为「全不命中」。
8. **融合参数可配**：RRF 的 k 与向量/关键词权重可经配置改变，改变后同一输入的融合结果随之变化且不抛异常；默认 k=60。
9. **无新增 MCP 工具**：`tools/list` 仍为既有工具集合；`retrieve` 的成功响应 JSON 顶层键恰为 `chunks` 加可选的 `degraded`（布尔）与 `degraded_reasons`（列表）——**字段名逐字见 §B3，两侧不得另立名称**；三者之外出现任何顶层键即失败；`degraded` 缺省即未降级，`degraded_reasons` 缺省即空。

### B. 默认启用所有功能

10. **默认全开且为硬断言**：在只配置连接类地址与凭证、不设置任何能力开关的默认配置下，能力开关矩阵中「已实现」的每一项均为 on，启动自检输出的关闭项列表长度 = 0；长度 > 0 时该检查 exit 非 0（即使其余测试通过）。
11. **重排默认开启**：默认配置下一次 `retrieve` 调用，重排被调用 1 次（注入 fake reranker 计数 = 1）；重排失败时保留 fail-open 语义（返回重排前顺序、不向 Host 抛错），但**必须**按 §B3 置 `degraded` 为 true 并在 `degraded_reasons` 中写明重排项——无标记的 fail-open 即为失败。
12. **图默认启用**：配置了图谱地址时，默认配置下一次 `retrieve` 走 **Neo4j graph arm**（种子 → **PPR**），断言图臂被调用 1 次；图谱地址**缺失**时（默认启用的能力无法尝试）按 §B3 置 `degraded` 为 true 并在 `degraded_reasons` 中写明图多跳检索项——不再沿用「missing URI 即 skip 且不 `degraded`」的旧语义。
13. **凭证缺失不再伪向量**：**embedding credentials** 缺席时，一次 `retrieve` 的 envelope 携带 `degraded` 为 true 且 `degraded_reasons` 含向量检索项；结果中不含任何由确定性伪向量计算出的命中——**两条断言都必须成立，任一不成立即本条失败**（不再二选一）：
    - **主判据**：注入的 embedder 调用计数器显示该次 `retrieve` 中 embedder 调用次数 = 0（> 0 即失败）；
    - **并列判据**：把嵌入函数替换为「调用即抛 typed error」的替身后重放同一请求，返回的命中 id 序列与未替换时逐项相同，且无异常上抛、无空结果冒充命中。「静默降级为伪向量」这一路径不复存在。

### C. 不二次切分、幂等与失效

14. **不二次切分**：一次 `ingest` 传入一条内容，落库恰好 1 个 **chunk**，其文本与入参文本逐字节相同（长度与内容双断言）；长文本传入时不产生第二条块、不被截断、不被归一化改写；`retrieve` 返回的该块文本同样逐字节相同。
15. **入库幂等**：同一（`source_ref`，内容标识）连续 ingest 的次数取 §B1「幂等基准」行（见 §B1），chunk 行数增量 = 0（不是 1，也不是该次数），且每次返回的 chunk id 完全相同；幂等键定义见 §B4。
16. **内容失效**：提供一个失效动作，对一个已入库 chunk 执行后，以任意 `valid_at` ≥ 失效时刻发起的 `retrieve`，结果中该 chunk id 出现次数 = 0；该 chunk 行仍在表中（行数不变）且不参与检索结果；重复执行同一失效请求结果一致（幂等）；每次失效留下可查询的失效记录（chunk 标识、失效时刻、触发方）。不提供物理删除路径。
17. **批量入库（规模）**：**批量上限可配且有默认值**（默认取值不进本 spec，见 §实现者余地）。断言：配置中的批量上限 > 0 且为有限值（为 0 / 缺失 / 非数值 → typed error）；一次批量 ingest 达到该上限条数时，返回的 chunk id 数 = 该上限，落库行数增量 = 该上限；幂等键相同的一批重复提交不产生增量行（增量 = 0）。
18. **连接池参数生效**：设置连接池上限后，并发检索期间观测到的实际并发连接数超过该上限的次数 = 0；参数非法 → `ConfigError`。

### D. 评测体系

19. **真实数据注入**：清单文件中每个源条目都带来源标注；缺失来源标注的条目被校验器拒绝（校验 exit 非 0）。数据集构建入口导入后，落库 chunk 行数 = 清单声明行数。
20. **文件格式覆盖**：文件格式清单为 PDF、Word、PPT、Excel、HTML、Markdown、纯文本（与 fin 侧同一份资产清单）；**覆盖的种数与每种格式的源文档数下限**取 §B1「数据集规模」行（见 §B1，本 spec 不另设一套）；覆盖数不足时校验 exit 非 0。
21. **查询类型覆盖**：查询分为实体锚定型（走图）、精确串型（走短语）、语义泛化型（走向量）、时效型（带 `valid_at`）四类；**每类占比下限**取 §B1「查询分档」行（见 §B1）；任一类占比未达下限时校验 exit 非 0。
22. **规模下限**：源文档数、chunk 数、查询数的下限均取 §B1「数据集规模」行（见 §B1）；查询分档（CI 契约集与全量集的题数、四类占比）取 §B1「查询分档」行（见 §B1）；任一下限未达时校验 exit 非 0。
23. **消融开关清单**：可独立开关的能力项恰为 §B4 列出的 8 项（逐项清单见 §B4，本条不另列一份）；每一项可独立 on / off。**「其他静默行为变化」的定义（可枚举，穷尽）**——关闭单项后与全开基线相比，**只允许**下列三类差异，其余任何差异一律视为静默行为变化：
    - **D1** 命中集合与排序发生变化（消融的目的，允许，且必须落进报告）；
    - **D2** 按 §B3 置 `degraded` 为 true 并在 `degraded_reasons` 中列出本次关闭的项（允许，且为必需）；
    - **D3** 报告与运行日志中记录本次关闭的能力项名称（允许，且为必需）。
    断言：对 8 个能力项逐个关闭并各运行一次，与全开基线逐项比对，不属于 D1 / D2 / D3 的行为差异条数 = 0。本条不枚举"所有可能的静默行为"——凡不落进 D1 / D2 / D3 的差异即按违反处理。
24. **消融配置矩阵**：覆盖的配置总数、配置构成（全开基线 + 逐项关闭 + 全关基线）与**每配置重复次数**均取 §B1「消融矩阵」行（见 §B1）；每配置落原始值与中位数；缺失配置数 = 0。
25. **量化输出且百分比是数字**：每个配置的报告含 §B1「指标集」行列出的**全部字段**（字段清单以 §B1 为唯一权威，本 spec 不另设一套），以及相对基线的百分比变化；其中引用门通过率由 fin 侧在同一份运行结果上产出、合并时填充，本侧不填充即视为该字段缺失；其余字段类型为 number 且为有限值；百分比 =（该配置值 − 基线值）/ 基线值 × 100，保留两位小数；基线的百分比变化 = 0；字段缺失、为字符串、或报告中用「明显提升 / 略有下降」类表述替代数字，则该次运行 exit 非 0；报告同时输出 JSON 与 Markdown，可 git diff。
26. **顺序性断言**：全开基线的 run-level P@5 ≥ 全关基线的 run-level P@5；违反则该次运行 exit 非 0。
27. **可复现**：同一 commit、同一数据集快照 id、同一配置连续两次运行，run-level P@5 与 R@5 完全相同（浮点容差 0）。
28. **gold provenance**：任一条 gold 缺失 provenance（来源文档 id / 判定方式 / 判定时间 / 判定模型 id）→ loader typed error；判定模型 id 等于生产抽取或嵌入模型 id → `ConfigError`。
29. **冻结 gold 不受影响**：`npm run eval:retrieve` 仍按其自身契约写出基线文件；`specs/retrieve-p5.md` 的查询数范围校验仍只约束它自己的 gold 文件（新增评测集与其**并存**，不合并）。

### E. 并发

30. **并发 L1 场景（检索 / 读取路径，不含 LLM）**：并发入口的**并发数、读写比、持续时长、总请求数下限**均取 §B1「并发 L1（检索 / 读取路径，不含 LLM）」行（见 §B1）；实际总请求数低于该下限时 exit 非 0。§B1「并发 L2（完整 run，含 LLM）」行的完整 run 场景由 fin 侧在同一份运行上产出，本侧不重算、不重复建模。
31. **错误率**：并发期间错误数 = 0（判定口径取 §B1「并发 L1（检索 / 读取路径，不含 LLM）」行的"错误数 = 0"；任何非 0 退出 / typed error / 5xx 均计入）；错误数 > 0 时 exit 非 0；p50 / p95 / p99 全部落盘（落盘要求取 §B1 同一行），缺任一分位即 exit 非 0。
32. **延迟阈值**：p95 与 p99 的上限取 §B1「延迟阈值」行（见 §B1，该行仅作用于并发 L1；L2 用其自身的 p50 / p95 判据）；预热请求不计入统计；任一分位未落盘或超上限即 exit 非 0。
33. **连接池不成为失败源**：并发期间因等待连接超时而失败的请求数 = 0（其余失败按 §B2 / §B3 处置，不计入本条）。契约只约束"连接等待超时上限 > 0 且被观测"——上限取值属实现者余地（见 §实现者余地），本 spec 不规定具体等待时长。断言：并发压测结束后，统计中存在"等待连接超时"这一独立失败类别字段（缺失该字段即视为未观测，判失败）且其计数 = 0。
34. **无结果串扰**：同一查询在并发下返回的结果 id 集合与串行基线一致的查询占比 ≥ 99%。
35. **三臂并发启动**：单次 `retrieve` 内，向量 / 关键词 / 图 三臂并发启动（start-order 或 timing seam 断言），不是串行等待。
36. **并发幂等场景**：**并发数与持续时长**取 §B1「并发幂等场景（全写）」行（见 §B1）；全写入、重复提交同一批内容，压测前后 chunk 总数增量 = 0（判定口径取 §B1 同一行），错误数 = 0。

### F. 降级与部分失败

37. **部分失败语义**：按 §B2 —— 构造「一臂失败、其余成功」：响应放行、`degraded` 为 true、`degraded_reasons` 含失败项、结果只含成功臂的命中；构造「全部失败」：返回 typed error，既不是空结果也不返回未标记的部分结果（即不得返回 `degraded` 为 false 的部分结果）；构造「向量臂失败且图无命中」：按全部失败处理，返回 typed error。三种构造全部符合才算通过。
38. **静默失败清零**：按 §B3 逐项断言——凭证缺失（SC-13，置 `degraded`）、图地址缺失（SC-12，置 `degraded`）、重排失败（SC-11，fail-open 并置 `degraded`）、精度层调用期失败（置 `degraded` 并在 `degraded_reasons` 中具名）、建索引条件不满足（非 0 退出，SC-2）、后台路径失败（可列举、可重放、重试幂等）；清单中出现"无痕迹的失败路径"条数 = 0。
39. **跨仓基线一致**：本 spec 与 fin 侧 spec 的「跨仓对齐基线」章节正文逐字节相同——按 §B6 的方式取两段正文分别计算 sha256，两值相等则通过，不等则失败。

### G. 回归

40. **套件与构建**：`npm run typecheck` exit 0；`npm test` exit 0；`npm run build` exit 0（外部依赖在配置层面未提供时 loud skip）。
41. **隔离**：评测与压测入口不 import 服务进程入口；既有隔离测试保持绿。
42. **不写图**：ADR-0001 不变——本 spec 的所有写入都在 Postgres 权威侧与派生索引；投影写入仍只走 **projection outbox** 与 backfill/drain 路径。

### H. 空输入与溢出（Testing Strategy 的 empty / overflow 两类在此具名化）

43. **空查询**：`retrieve` 收到空字符串或仅含空白的查询 → 返回 typed error（输入校验失败），exit ≠ 0；断言：不返回空结果列表冒充"命中为空"、不返回部分结果、**不**按 §B3 置 `degraded`（入参非法不是能力失败，误置位即失败）；该次调用被计入"输入校验失败"计数且该计数 > 0。
44. **空语料**：数据集构建入口导入后 chunk 行数为 0（清单为空或全部条目被拒）→ 以非 0 退出并给出具名错误；断言：不写出基线文件、不覆写既有基线文件（失败前后既有基线文件 sha256 不变）、不产出"全 0 指标"的报告冒充通过。
45. **空 gold**：查询清单中任一查询的 gold 列表为空 → loader 以 typed error 终止，exit ≠ 0；断言：不按"0 命中"计入指标、不静默跳过该查询；被拒查询的 id 逐条写入失败记录，记录条数 = 空 gold 的查询数。
46. **空内容推送**：`ingest` 收到空文本内容或空内容列表 → 返回 typed error，exit ≠ 0；断言：落库 chunk 行数增量 = 0，不产生空文本 chunk，不返回空 id 列表冒充成功；该次失败具名，且按 §B1「幂等基准」行不计入幂等断言。
47. **批量溢出具名**：单次 `ingest` 的内容条数**超过** SC-17 的批量上限 → 返回**具名溢出错误**（typed error，错误码与"内容非法"可区分），exit ≠ 0；断言：落库 chunk 行数增量 = 0，不静默截断为"只处理前 N 条"，不把被截掉的尾部分批入库；错误信息中同时给出实际条数与上限值。对照：条数**恰好等于**上限时按 SC-17 的成功路径处理，不报错。
48. **合法空结果**（与 §B2 第 5 条第二类对应）：以语法合法但无任何匹配的查询调用 `retrieve` → 返回成功响应与空结果列表，exit = 0，**不**置 `degraded`、**不**返回 typed error。断言：该调用被计入"输入校验失败"计数的次数 = 0；`degraded` 为 true 的次数 = 0；与 SC-43（空查询）在同一轮运行中结果必须不同。

**新依赖的排除论证 —— 为什么精度层不落在 Postgres 侧：**

**甲、对下列三条备选都成立的共同约束（先立判据，再逐项排除）：**

1. **索引期与查询期必须同源**：中文分词只有在两侧用同一分析器时才稳定；把分词与排序放进同一个词法引擎，天然同源，不会出现索引与查询词元不一致导致的召回漂移。
2. **四项词法能力必须作用于同一份词元流**：定档 B 要求中文分词、Okapi BM25、短语查询、字段加权同时生效；分散到两个引擎会出现"分了词但排序看不见"的割裂，也会出现"两处各自排序、再合流"的第二套口径。
3. **实例级运维约束**：权威源只保持"权威数据 + 一个向量扩展"的最小职责；任何实例级扩展都会把词法能力与 Postgres 主版本 / 构建、镜像、升级路径绑在一起。
4. **与"派生索引可重灌"冲突**：权威源与派生索引分离要求只有一个可重灌入口；词法栈落在权威源侧后，重灌要同时协调两侧，且词典升级会触发权威侧的数据变更，与"权威源稳定、派生可重建"相反。

**乙、逐项排除（三条 Postgres 侧方案，逐条给理由，不是只给结论）：**

- **P1 只换 Postgres 文本配置（不引入新依赖）**：**排除。** 文本配置只决定"哪些词元被保留、是否转小写、是否去停用词"，**不产生切分能力**。中文没有空格分隔，内置解析器按空格与标点切分，连续中文整体成为一个词元；换配置（含自建词典与停用词）只能做过滤，不能把"整体"切成词。因此缺口 1（中文词法臂召回趋近于零）不解决；词元只有一个时 tf 与长度归一化失去统计意义，缺口 3（缺长度归一化与词频饱和）也不解决；短语查询与字段加权在中文上仍无从参与排序。**结论：能力上就不成立，不是成本问题。**
- **P2 Postgres 侧中文分词扩展（zhparser / pg_jieba / pgroonga 一类）：排除。** 这条**能力上可行**——确实能切出中文词元，排除理由不在能力，而在它与定档 B 的硬约束冲突：① 这类扩展提供分词与检索算子，但 Okapi BM25 的 k1 / b 可调、短语查询参与排序、字段加权，以及它们与向量 / 图结果在同一条链路上合流，需要**一处排序权威**；把其中几项留在权威源侧，就出现第二套排序口径，违反共同约束 2。② 需要在数据库实例上安装并编译、与 Postgres 主版本 / 构建绑定，权威源的镜像、升级与故障恢复都要带上它，违反共同约束 3。③ 词典更新要重建文本索引，属于权威源数据变更，与"删派生索引 → 重灌 → 数据不丢、质量不回归"这条可验证路径相反，违反共同约束 1 与 4。**结论：可行但与权威 / 派生分离、四项同源两条硬约束冲突，排除。**
- **P3 pg_bigm 一类的轻量 N-gram 方案：排除。** 优点是安装轻、无需词典、不挑版本，但代价在精度侧：① **不做词义切分**，二元组把连续中文切成彼此重叠的片段，噪声词元数量级放大，精确串型与实体锚定型查询的精度下降——与"精确串参与排序""图找实体"两处目标方向相反。② **Okapi BM25 的 tf 语义被破坏**：词频统计对象从词变成 N-gram 片段，词频饱和与长度归一化的统计意义改变，k1 / b 的调参不再对应词级行为，缺口 3 只被部分且不可预期地改善。③ **短语查询与字段加权仍需另一套实现**（N-gram 索引不提供用于排序的短语位置信息），四项能力依旧分散。④ **索引膨胀**：二元组词元数相对词元数放大，写入放大与索引体积增长落在权威源侧。⑤ 它**仍是实例级扩展**，未解除 P2 的 ②③ 两条约束，只是把安装成本降下来。**结论：轻量但不解决四项同源，且引入精度与膨胀的反向代价，排除。**

**丙、结论：** 三条 Postgres 侧方案逐一排除后，中文分词、Okapi BM25、短语查询、字段加权合为**一个精度层**，由 Elasticsearch 承担；Postgres 侧只保留权威数据 + 一个向量扩展，不再保留第二套词法排序实现。由此引入 Elasticsearch 客户端作为新运行时依赖，是定档 B 的必然结果（不再是待确认项）。

- **C-3 重排改判**：`specs/retrieve-rerank-llm.md` 的「Default off / 缺 token skip 不 `degraded`」被改判为「重排默认开启；缺 token 视为默认启用的能力无法尝试 → 置 `degraded`；调用失败保留 fail-open 但必须置 `degraded` 并在 `degraded_reasons` 中写明重排项」。→ 需同步修订：`specs/retrieve-rerank-llm.md`、`specs/retrieve-graph-quality.md`（其专用重排 slice 的 default-off）、CONTEXT.md **rerank**（待写入）。
- **C-4 默认启用范围定稿**：「默认启用所有功能」覆盖本 spec 定义的检索栈能力项，**不**覆盖 **community** topic retrieve 与 **neighbor evidence**（保持现状，不计入自检与消融）。此条不再是开放问题，`specs/retrieve-graph-quality.md` 与 `specs/retrieve-community.md` 的 default-off 无需改动。
- **C-5 评测资产扩容（并存，非覆盖）**：新增第二套评测集（真实数据、多格式、多查询类型、规模下限、消融矩阵、并发入口），数字口径与 fin 侧一致，报告可合并。`specs/retrieve-p5.md` 的冻结 gold 与其查询数范围校验**保持不变**；**不与新增评测集合并**（原 Q12 已定稿为并存）。
- **C-6 降级语义扩展与统一**：CONTEXT.md **degraded=true** 现有规则为「没找到不算降级；运营方关掉的不算降级；missing Neo4j URI 也不 degrade」。本 spec 按 §B3 统一：**默认启用的能力无法尝试（含凭证 / 地址缺失）→ 置位**，即改判「missing URI 不 degrade」；「未找到不算降级」与「显式关闭不算降级」两条保留。→ 需同步修订：CONTEXT.md **degraded=true**、**Neo4j graph arm**（其「missing URI skips without `degraded`」）、`specs/neo4j-graph-arm.md`、`specs/retrieve-graph-priority.md`（待写入）。
- **C-7 权威与派生的范围扩展**：ADR-0001 的「派生、可重建」从图投影扩展到检索索引（向量索引与词法索引）。新增 ADR **ADR-0003「权威源与派生检索索引分离；向量库可平滑升级」**，不改写 ADR-0001。
- **C-8 新运行时依赖**：Elasticsearch 客户端。§Tech Stack 已给出排除论证，该依赖是定档 B 的必然结果。
- **C-9 写入侧新增能力**：入库幂等、内容失效、批量入库、连接池参数可配——均落在权威源侧与入库路径。幂等的**实现手段**属实现者余地；若选择加唯一约束则按 `specs/p0-schema.md` 的 Ask-first 先问。
- **C-10 部分失败与静默失败语义定稿**：新增 §B2 / §B3。此前未定义的「多臂中一路失败」按「一臂成功即放行并标记、全失败即具名失败」处理；此前未定性的 skip vs fail-open 按「配置层面未提供 → loud skip；已配置而调用期失败 → 置 `degraded` 并在 `degraded_reasons` 中具名」二分处理。
- **C-11 切分归属改判（方向与既有 CONTEXT 相反）**：CONTEXT.md **chunk**（"produced by the chunker during ingest"）、**ingest**（"validate → size check → chunk → embed → store"）与关系表「**content → chunker → chunk[]**」把切分写成本仓库自身的入库步骤。本 spec 按定档 B 改判：**切分归 fin，本仓库不做二次切分**（§B4），入库不再承担切分职责，不保留双路径。→ 需同步修订：CONTEXT.md **chunk**、**ingest** 与关系表（待写入）；`specs/p0-extraction.md`（其 out-of-scope 把切分实现列为"不改动"的既有件）、`specs/p0-integration.md`、`specs/bm25-retrieve.md`、`specs/retrieve-p5.md` 的既有 out-of-scope 条款需从「多粒度切分不在本仓库」升级为「任何切分都不在本仓库」。
- **C-12 跨仓对齐基线**：与 fin 侧共享同名章节，统一数字口径与跨仓契约字段，并以逐字比对作为验收（SC-39）。
