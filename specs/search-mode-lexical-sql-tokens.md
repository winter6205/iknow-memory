## Objective

Give the last two bare-letter 检索档 tokens their word forms on the **retrieve** wire: **`A` → `lexical`**, **`D` → `sql`**. The lasting closed set of `filters.search_mode` becomes **`lexical | graph | global | sql`**; `graph` and `global` are already live and **do not move**. This repo **expands and retires in ONE step** (header ruling): the dispatcher resolves only the four word tokens, and every retired letter — `A`, `B`, `C`, `D` — is a typed `invalid_search_mode` refusal. Pre-release there is no alias window: fin retokenizes its entry seams **after** this set ships, not the other way around. Every 档 keeps **its own arm and its own ranking** — this is a retokenizing, not a re-implementation: **`lexical`** runs the existing child→parent 抽图窗 arm (ADR-0060), **`sql`** keeps throwing the typed 真库未接 refusal, and the default for a missing key stays **`graph`**. Envelope stays `{ chunks[] }` (+ optional `degraded` / `degraded_reasons`); the host still writes the answer.

**Who:** MCP host (**fin** syncs the same tokens in the sibling spec above); operators querying a **资料集合**.

**Token map** (retired → lasting → operator label → what this repo's arm actually does):

| retired | lasting | label (fin's, unchanged) | arm in `SEARCH_MODE_ARMS` |
| --- | --- | --- | --- |
| `A` | **`lexical`** | 查找 | `modeAParentWindowArm` — child lexical/ES hit → parent 抽图窗 body (ADR-0060); retitled only |
| `B` | `graph` | 知识问答 | `assembleRetrievalResult`; **still `DEFAULT_SEARCH_MODE`, the answer to a missing key** |
| `C` | `global` | 综述 | `modeCReportFirstArm` — report ES ∥ report vectors (ADR-0070) |
| `D` | **`sql`** | 真数据库 | `modeDNotWiredArm` — typed `real_db_not_wired` throw; no SQL runs |

**Ownership of the enum:** this repo owns the **wire enum** (`SEARCH_MODES`, `src/core/retrieval/search-mode.ts:55`) — it is what the server accepts or refuses. fin owns its **host-side** closed set in `src/fin/retrieve/tiers.py`, which is fin's SSOT and is deliberately wider on input (`TIER_INPUT_TOKENS`). One canonical spelling travels the wire and lands in fin's audit; on this side no retired letter exists in any wire table at all — `SEARCH_MODES` is the only closed set — and fin sheds its letters at the entry seams per its own ticket.

Quoted from this repo `docs/CONTEXT.md` (exact copy, not redefinition): **retrieve**, **hybrid retrieval**, **Neo4j graph arm**, **community**, **community level**, **rerank**, **degraded=true** — as quoted in [`search-mode-graph-global.md`](search-mode-graph-global.md). Fin **检索档** / **抽图窗** / **具名失败** apply as joint product names and are not redefined here.

## Confirmed assumptions (gate)

1. Parent [`search-mode-retrieve.md`](search-mode-retrieve.md) still owns the **`lexical`** arm (child lexical hit → parent 抽图窗 cite, ADR-0060) and **`sql`**'s typed 真库未接 refusal; [`search-mode-graph-global.md`](search-mode-graph-global.md) still owns `graph` mix-before-rerank and `global` report-first. **This file opens no arm and changes no ranking.**
2. Closed set is `lexical | graph | global | sql` — `SEARCH_MODES` (`src/core/retrieval/search-mode.ts`) in that spelling, and `SearchMode` derives from it. `A` and `D` stop being accepted in the same commit that adds the word forms — they are refused outright, not demoted to an alias table: no spelling of a letter resolves anywhere on this side.
3. **`DEFAULT_SEARCH_MODE` stays `"graph"` and stays a literal.** It must never be derived from `SEARCH_MODES[0]`: sorted alphabetically the set begins `global`, which would silently move every omittant caller onto the report-first 综述 档 — a ranking change, not a rename. `parseSearchMode` resolves from the closed set alone, so missing → `graph` byte-for-byte.
4. **`SEARCH_MODE_ALIASES` is deleted** — the proposed `A`/`D` entries never ship, and the already-live `B`/`C` pair goes with them, together with the alias branch in `parseSearchMode` and the `searchModeAliasHints()` helper. The letters exist in **no** wire-side table; `SEARCH_MODE_ARMS` keeps exactly one row per lasting token and no arm, table row or envelope reader may branch on a letter. `lexical: modeAParentWindowArm`, `sql: modeDNotWiredArm`.
5. **This step retires all four letters.** Expand and retire land in ONE ticket (header ruling): after it ships, `A`/`B`/`C`/`D` each take the `GraphragError("INVALID_INPUT")` path carrying `invalid_search_mode`. The order dependency runs the other way now: a host still sending a letter meets a refusal this spec *intends* — pre-release, zero letter coexistence is the accepted state — and fin's retokenizing is downstream of this landing, not a blocker for it.
6. Naming debt is **not** folded in here: `src/core/retrieval/mode-a-arm.ts` / `modeAParentWindowArm` and `mode-c-arm.ts` / `modeCReportFirstArm` (plus `filters.c_drop_windows` and the `modeD*` spelling) are retired-letter names. The letters being dead on the wire does not fold the rename in either: the ruling reached the wire **values**, not the source-level names, so the rename stays its own contract ticket under graph-global plan **T4**'s owner rule — file/symbol renames of everything named after a retired letter happen in the ticket that carries them, **"not as a drive-by"**.
7. `SEARCH_MODE_WIRE_COPY` is **derived** from `SEARCH_MODES` alone (a plain `join(" | ")` once the alias hints are deleted), so the MCP tool description and the refusal message move together with the set and need no literal edit. The one **non-derived** exception is `realDbNotWiredMessage()`, whose prose reads `search_mode=sql is not wired` while its reason token `real_db_not_wired` stays byte-identical for fin's mapping.
8. `sql` is a name for a 档 that **still refuses**: no SQL is invented, no fake business-DB answer is produced over chunks, document tables stay on `graph`, and the refusal stays `GraphragError(…, "INVALID_INPUT")`. Renaming it now is cheap; after a real wiring ships it would drag the wiring, its tests and the operator's spelling with it.
9. Invalid values (`""`, `local`, `E`, and every retired letter `A`/`B`/`C`/`D`) are typed `invalid_search_mode` refusals — never `degraded=true`, never a healthy `{ chunks: [] }` standing in for "no such 档". Envelope shape unchanged; **one** `retrieve` MCP tool; no generate/map-reduce tool; the host still writes the user-visible answer.
10. `npm run typecheck` + `npm test` pass on the touched suites with hermetic fakes — no live ES / GDS / PG, and no dependency on fin at all: after the one-step ruling the wire dependency runs exactly one way (assumption 5) — this set ships, fin follows. Hermetic green is the **development** gate only: it never counts as done for a wire-contract change (this repo's and fin's test rules both require a live item — SC9). Credentials stay in `~/.iknow-memory/setting.json` / existing env; no secrets in tests or docs.
11. **The 档 is resolved PER CALL, never at construction time.** `parseSearchMode(args.filters)` is the only reader of a request's 档, and `SEARCH_MODE_ARMS` maps token → arm (a constant table), not run → 档: nothing here may memoize a resolved mode on a server, deps bundle, or module binding. The reason is on the host side and is load-bearing for this rename: fin's compiled graph passes through an idempotence cache (`fin.host.graph._IDEMPOTENCE_CACHE`, `src/fin/host/graph.py:3538`, key at `:3558-3583` — those are fin's LANDED worktree numbers, fin main is behind) keyed on graph identity only, so ONE graph object serves every run of the process — any construction-time 档 would leak across runs and threads. Same argument in this repo's own shape: an arm that captured a mode would answer a `sql` request with a `lexical` corpus read.

## Success Criteria

1. `npm run typecheck` exits 0 and `npm test` exits 0 on the suites this change touches, with hermetic fakes (no live ES/GDS/PG, no fin checkout required).
2. `search_mode=lexical` runs `modeAParentWindowArm` and cites the parent 抽图窗 on the existing child-lexical fixture — the assertions the old `A` case carried now stand on the `lexical` token alone. `search_mode=A` is a typed `invalid_search_mode` refusal (`tests/retrieval/search-mode.test.ts`, "types every single letter invalid").
3. `search_mode=sql` throws the typed refusal whose message names `sql` and whose stable token is still `real_db_not_wired`; `search_mode=D` never reaches that arm — it is a typed `invalid_search_mode` refusal. Neither path returns `{ chunks: [] }` and neither sets `degraded`.
4. Missing `search_mode` routes `graph` — asserted independently of `SEARCH_MODES` ordering (reorder or extend the set and the assertion still holds).
5. `SEARCH_MODE_ARMS` has exactly four keys, all word-form, and no arm, table row or envelope path resolves **on** a letter; the retired-letter identifiers and comment prose that remain in source are assumption 6's deferred debt, not dispatch behaviour.
6. `SEARCH_MODE_WIRE_COPY` renders `lexical | graph | global | sql` and no letter (`\b[ABCD]\b` finds nothing), and is interpolated — not duplicated — by the tool description and by `invalidSearchModeMessage`; the description keeps one deliberate non-derived literal as a drift canary.
7. `graph` and `global` behaviour is unchanged: the graph-arm prefix order, mix-before-rerank placement, `global` not-ready → `community_summary_index_failure`, `c_drop_windows=0`, and the ADR-0060 exit paths all keep their existing assertions.
8. Envelope unchanged (`{ chunks[] }` + optional `degraded` / `degraded_reasons`); still exactly one MCP `retrieve` tool; dashboard and MCP paths still share the dispatcher (no second ranker).
9. **LIVE (必选, not satisfiable by fakes):** a real round trip against a booted server on real PG + ES (this repo's `tests/integration/*-pg.test.ts` convention — env-gated, excluded from the CI fast job; e.g. `GRAPHRAG_MEMORY_*` per `tests/integration/neo4j-ppr-arm.test.ts`'s documented header) proves over the wire that `filters.search_mode=lexical` reaches the child→parent 抽图窗 arm and returns the PARENT body, that `sql` returns the thrown `real_db_not_wired` message naming `sql`, that a missing key is answered by `graph`, and that every retired letter `A`/`B`/`C`/`D` sent over the wire arrives back as a typed `invalid_search_mode` refusal carrying `SEARCH_MODE_WIRE_COPY` (the letter-refusal case in `tests/integration/retrieve-search-mode-pg.test.ts`). Fake-only green does not close this increment (fin's `-m mcp` driver, sibling SC8, is its mirror).
